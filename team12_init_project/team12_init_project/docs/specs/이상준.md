# Farmcare 예약 문의 누락 정보 확인 — 이상준

상태: 사용자 위임에 따라 기본값으로 작성·구현한 명세서. 필수 항목·검증 규칙은 Farmcare의 확정 운영 정책이 아닙니다.

연결 노드: 농장의 안정적인 체험 운영 > 예약 오류 줄이기 > 예약 전 누락 정보 확인
구현: prototypes/이상준/

## 1. 대상과 문제 발생 순간

Farmcare 운영자가 감 수확 등 농촌 체험에 대한 전화·메시지 문의를 접수할 때 사용합니다. 정보가 한 문장에 섞여 있거나 인원·시간·연락처가 누락되어 재확인이 필요합니다. 방문 가족이 직접 이 도구를 사용하는 것으로 전제하지 않습니다.

## 2. 사용자 흐름

1. 운영자가 문의 메모를 입력합니다. 빈 입력은 허용하지 않고 5,000자로 제한합니다.
2. ‘메모에서 항목 찾기’를 누릅니다. 인식 가능한 일부 표현만 규칙으로 추출합니다.
3. 운영자가 원문과 추출 결과를 대조하고 각 필드를 직접 수정합니다.
4. ‘수정 내용으로 확인’을 누르면 누락·오류·추가 질문과 다음 행동을 보여줍니다.
5. ‘확인 결과 복사’로 결과를 가져갑니다. 브라우저가 자동 복사를 막으면 직접 복사할 수 있는 선택 영역을 제공합니다.
6. 문의 또는 필드를 바꾸면 이전 결과를 만료하고 복사를 비활성화합니다. 다시 확인해야 최신 결과가 됩니다. 복사 대체 영역에 남아 있는 이전 결과도 숨깁니다.

## 3. 과제용 기본 필수 항목

체험 상품, 방문 날짜, 희망 회차·시간, 성인 인원, 아이 인원, 아이 나이, 예약자 이름, 연락처입니다. 아이 인원이 0이면 아이 나이는 제외합니다. 상품 운영 조건·정원·연령 기준은 별도 자료가 없으므로 판단하지 않습니다.

날짜는 YYYY-MM-DD이며 실제 존재하는 날짜인지 확인합니다. 기준일은 실행 기기의 날짜이며 과거 날짜는 다시 확인하도록 안내합니다. ‘이번 토요일’ 같은 표현은 날짜로 확정하지 않습니다. 인원은 0 이상의 정수이고 합계는 1명 이상입니다. 아이 나이는 숫자를 쉼표로 구분하고 아이 수와 개수를 대조합니다. 연락처는 국내 휴대전화 형식만 확인하며 실제 소유 여부는 확인하지 않습니다.

## 4. 우선순위

| 우선순위 | 항목 |
|---|---|
| P0 | 문의 입력, 부분 추출, 필드 수정, 필수 항목 누락 확인, 날짜·인원·나이 개수·연락처 형식 검증 |
| P0 | 날짜·인원 후보가 여러 개면 임의 선택하지 않고 후보 충돌 안내 |
| P0 | 누락 항목 질문·다음 행동 제시, 결과 복사 및 복사 실패 대체 방법 |
| P0 | 이전 결과 만료, 명확한 초기·누락·완료·오류 상태, 전체 초기화 |
| P1 | 상품별 필수 항목 설정, 원문과 추출 근거 나란히 보기, 문맥 추출 고도화 |
| P2 | 서버 측 AI 모델 연동, 실제 상품 DB·정원 연동, 예약 상태 관리 |

## 5. 범위 밖

예약 확정, 결제, 고객에게 메일·문자 발송, 실제 상품 검색·추천, 가격·정원·보험·연령 적합성 판단은 하지 않습니다. 문의 한 건만 다루며 저장·동기화·회원 기능은 없습니다. 추출기는 한국어 일부 패턴만 지원하며 일반 자연어 이해 모델이 아닙니다.

## 6. AI 모델과 실패 대응

이번 프로토타입 실행 중 AI 모델을 사용하지 않습니다. GPT/Codex는 개발을 돕는 도구로 사용하며 앱 자체는 JavaScript 규칙 기반입니다. API 키·네트워크 호출·외부 의존성이 필요 없습니다. 인식되지 않은 정보는 빈칸으로 남겨 사람이 보완합니다. 정보가 모두 있어도 ‘운영자 확인 필요’로 표시합니다.

빈 입력·길이 초과는 안내하고 원문을 보존합니다. 복사 실패 시 직접 복사 영역을 표시합니다. 처리 오류는 입력을 유지하고 재시도할 수 있게 안내합니다. 실제 모델 호출 실패 테스트는 모델 미사용으로 해당 없음입니다.

## 7. 직접 수행할 수동 체크 3개

| 체크 | 조작 | 기대 결과 | 작성자 실제 결과 |
|---|---|---|---|
| 정상 | ‘정상 입력’ 예시를 불러오고 원문 대조 후 결과 복사 | 항목 추출, 누락 0개, 예약 미확정 안내, 복사 또는 수동 복사 | 미실시 — 작성자가 직접 확인 후 기입 |
| 누락·충돌 | ‘누락 입력’·‘충돌 입력’ 예시 확인. 날짜·나이 개수 수정 | 기한을 임의 추정하지 않음, 날짜 후보 충돌·나이 개수 불일치 표시, 수정 후 갱신 | 미실시 — 작성자가 직접 확인 후 기입 |
| 실패·상태 | 빈 메모 처리, 결과 생성 후 필드 변경, 복사 권한 거부 | 빈 입력 안내, 기존 결과 만료·복사 비활성화, 복사 실패 대체 영역 | 미실시 — 작성자가 직접 확인 후 기입 |

## 8. 구현 중 명세 변경 기록

- v0: 자연어 메모의 자동 추출 중심으로 구상했습니다.
- v1: 외부 모델 설정 없이 실행하도록 일부 패턴 추출 + 운영자 수정으로 범위를 명확히 했습니다.
- v1: 날짜·인원 후보를 임의로 선택하지 않는 규칙, 결과를 수정한 뒤 재검증하는 단계를 포함했습니다.
- 수정 요구가 생기면 이 명세서에 먼저 반영한 후 코드를 변경합니다. 현재 규칙을 바꾸지 않고 회고에 가상의 변경 경험을 적지 않습니다.

## 9. /grill-me 진행 상태

공식 Matt Pocock 저장소의 grill-me 및 연결되는 grilling 지침을 확인했습니다. 실제 /grill-me 슬래시 명령은 실행하지 않았습니다. 원문이 요구하는 상호 인터뷰 대신, 사용자의 명시적 위임에 따라 에이전트가 질문별 추천안·결정·이유를 기록한 설계 검토를 수행했습니다. 사용자는 미정 사항을 에이전트가 기본값으로 결정해 제작하도록 위임했습니다. 이는 기능 제작 권한이지 /grill-me 완료 증거가 아닙니다. 이 작업을 실제 슬래시 명령 실행으로 표시하지 않습니다. 위임형 검토 기록은 prototypes/이상준/DECISIONS.md에 있습니다. 해당 방식의 과제 인정 여부는 별도입니다.
