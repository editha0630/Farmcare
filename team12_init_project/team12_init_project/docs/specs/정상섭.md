## 1. 한 줄 요약

도시 가족이 팀원 가족 농장의 감 수확 체험(11/14~15, 가족 1팀 3만 원)을 **계좌이체 선입금으로 예약**하는 작은 웹사이트를 만든다.
이 웹사이트로 "도시 가족이 돈을 내고 예약하는가"를 검증한다.

**성공 기준:** 지인이 아닌 가족 **10팀 이상 입금**하면 성공이다. 5~9팀이면 다시 시험하고, 5팀 미만이면 방향을 다시 검토한다.
모집 기간은 **11/3(화) ~ 11/11(수), 9일**이다. 결과가 5~9팀이면 "모집 기간이 부족했는지"도 원인 후보로 본다.

## 3. 사용자

| 사용자 | 누구인가 | 이 웹에서 하는 일 |
|---|---|---|
| **고객** (주 사용자) | 농장에서 차로 1시간 안 도시에 사는, 아이가 있는 가족. 맘카페나 당근마켓 글을 보고 들어온다. 팀원의 지인이 아니다. 대부분 **휴대폰**으로 접속한다. | 체험 정보를 보고, 회차를 골라 예약을 신청하고, 계좌로 입금한다. |
| **운영자** | 팀원. 입금 확인은 가족 농장 팀원(미정)이 맡고, 대신할 사람 1명(미정)을 둔다. | 로그인해서 명단을 보고, 입금을 확인하고, 예약 상태를 바꾸고, 직접 문자를 보낸다. |
| **농장주** (간접 사용자) | 팀원 가족, 고령 농업인 | **웹을 쓰지 않는다.** 체험비를 본인 계좌로 받고, 체험 당일 농장을 연다. |

농장주가 웹을 쓰지 않게 한 것은 일부러 정한 것이다. PREMORTEM 1번(고령 고객의 디지털 부담)을 피하기 위해서다.

## 5. 예약 규칙

### 5-1. 회차와 정원

- 회차는 4개다: 11/14 10:00, 11/14 14:00, 11/15 10:00, 11/15 14:00.
- 회차당 최대 **5팀**까지 받는다.
- 정원을 셀 때는 **입금 대기와 예약 확정을 모두 포함**하고, 취소는 빼고 센다.
- **11/11(수) 23:59가 지나면** 모든 회차의 신청을 막는다.

### 5-2. 인원과 가격

- 1팀은 **최대 4명**이고, 가격은 **30,000원**이다. 감 5kg 1상자가 포함된다.
- **만 3세 미만(36개월 미만)** 아이는 인원에서 빼고 무료다. 현장 파악을 위해 "만 3세 미만 아이 ○명"은 따로 적게 한다.
- **5명 이상 가족은 2팀으로 예약**한다. 2팀이면 60,000원이고 감은 10kg이다. 입금 금액은 30,000원 또는 60,000원만 생긴다.

### 5-3. 중복 예약

- 같은 전화번호로 **진행 중인 예약(입금 대기 + 예약 확정)은 최대 2건**까지만 허용한다. 취소된 예약은 세지 않는다.
- 3번째 예약을 시도하면 "이미 예약이 2건 있습니다. 변경은 문자로 문의해 주세요"라고 안내한다.
- 전화번호는 숫자만 남겨서 저장한다. 그래서 `010-1234-5678`과 `01012345678`을 같은 번호로 본다.

### 5-4. 예약 상태와 입금

- **입금 대기:** 신청서를 냈다. 자리는 임시로 잡아둔다.
- **예약 확정:** 입금을 확인했다.
- **취소:** 기한 안에 입금하지 않았거나 취소했다. 자리가 다시 열린다.
- 신청 후 **24시간** 안에 입금하지 않으면 운영자가 직접 취소한다.
- **기한이 지난 뒤 입금한 경우:**
  - 그 회차에 자리가 남아 있으면 **확정**한다. 이미 취소한 예약이라면 다시 확정으로 바꾼다.
  - 자리가 없으면 같은 주말 다른 회차를 제안하고, 고객이 원하지 않으면 **전액 환불**한다.

### 5-5. 환불

| 상황 | 처리 |
|---|---|
| 고객이 11/11까지 취소 | 전액 환불 |
| 고객이 11/12 이후 취소하거나 당일 오지 않음 | 환불하지 않고 감 5kg을 택배로 보냄 (택배비는 고객 부담, 주소는 문자로 받음) |
| 농장 사정으로 취소 (비, 강풍, 감 부족 등) | 고객이 전액 환불이나 같은 주말 다른 회차로 변경 중에서 선택 |
| 기한이 지난 입금인데 자리가 없음 | 다른 회차를 제안하고, 원하지 않으면 전액 환불 |

### 5-6. 성공 기준 집계

- **입금한 시점**을 기준으로 센다. 기한이 지난 뒤 입금한 경우도 포함한다. 환불한 팀은 따로 표시한다.
- **지인의 범위:** 팀원 4명과 농장주 가족이 **직접 연락해서 알려준 사람**만 지인으로 본다.
- 팀원과 가족은 지인에게 **지인 전용 링크(`?from=friend`)**만 보낸다.
- **판정 방법:** 꼬리표나 "알게 된 경로" 답 중 **하나라도 지인을 가리키면 지인**으로 센다(보수적 기준).

| 유입 꼬리표 | "알게 된 경로" 답 | 판정 |
|---|---|---|
| `friend` | 무엇이든 | 지인 |
| `momcafe`, `daangn` | 지인 소개 | 지인 |
| `momcafe`, `daangn` | SNS, 지역 커뮤니티, 기타 | 지인 아님 |
| 꼬리표 없음 | 지인 소개 | 지인 |
| 꼬리표 없음 | 그 외 | 지인 아님 |

## 6. 사용 절차

### 6-1. 고객

1. 맘카페나 당근마켓 글에 있는 링크를 누른다. 링크에는 `?from=momcafe` 같은 꼬리표가 붙어 있다.
2. 예약 화면에서 농장 소개, 일정, 가격(3만 원, 감 5kg 포함), 인원 기준, 안전 수칙, 환불 규칙을 읽는다.
3. 4개 회차 중 **남은 자리가 있는 회차**를 고른다. 정원이 찬 회차는 "마감"으로 보이고 고를 수 없다.
4. 다음 정보를 입력한다.
   - 이름, 휴대폰 번호
   - 인원: 어른 ○명, 어린이 ○명 (합계 최대 4명). "5명 이상이면 2번 예약해 주세요" 안내가 함께 보인다.
   - 만 3세 미만 아이 ○명 (인원 합계에 포함하지 않음)
   - 입금자명: 예약자 이름이 미리 채워져 있고, 다르면 고친다.
   - 알게 된 경로
   - 개인정보 동의 체크
5. "예약 신청"을 누른다. 버튼은 한 번 누르면 잠긴다. 예약 상태는 **입금 대기**가 되고, 자리는 임시로 잡힌다.
6. 완료 화면에서 다음 내용을 확인한다.
   - 계좌번호(농장주 명의)와 복사 버튼
   - 입금 금액 30,000원
   - **입금 마감 시각(신청 후 24시간, 한국 시간)**
   - 환불 규칙
   - "이 화면을 캡처해 두세요" 안내
7. 계좌로 입금한다. 완료 화면을 놓쳤다면 **예약 화면 맨 아래 "입금 안내" 칸**에서 계좌번호, 예금주, 금액을 다시 보고 복사할 수 있다.
8. 운영자가 보낸 **확정 문자**(농장 주소, 안전 수칙 포함)를 받는다.
9. 체험 당일 농장에 와서 장대로 감을 따고, 감 5kg 1상자를 가져간다.
10. 다음 날 설문 링크 문자를 받고 3문항에 답한다.

### 6-2. 운영자

1. 매일 21:00에 운영자 화면에 로그인한다.
2. **입금 대기** 명단과 농장주 계좌의 입금 내역을 입금자명과 금액(3만 원 또는 6만 원) 기준으로 맞춰본다.
3. 입금이 확인된 예약은 **예약 확정**으로 바꾸고, 미리 만들어 둔 확정 문자를 보낸다.
4. 신청 후 24시간이 지나도 입금이 없는 예약은 **취소**로 바꾸고, 취소 문자를 보낸다. 그러면 자리가 다시 열린다.
5. 기한이 지난 뒤 입금이 들어오면 5-4의 규칙대로 처리한다. 취소한 예약을 다시 확정할 때도 정원은 넘길 수 없다.
6. 고객이 취소를 요청하면 환불 규칙에 따라 처리하고, 환불한 경우 **환불 표시**를 한다.
7. 11/13 17:00까지 비가 올지 판단하고, 체험을 할 수 없으면 우천 문자를 보낸다.
8. 회차별 남은 자리와, 지인 여부와 유입 경로별 입금 팀 수를 보고 성공 기준과 비교한다.

## 7. 개발 제외 범위

이번에는 **만들지 않는다.** 모두 11/2 마감을 지키고, 사업자등록이 필요한 기능을 피하기 위한 결정이다.

| 만들지 않는 것 | 대신 하는 것 |
|---|---|
| 카드결제, 간편결제 (PG 연동) | 계좌이체 선입금 |
| 자동 문자, 카카오 알림톡 | 완료 화면 안내, 예약 화면에 계좌 상시 표시, 운영자가 직접 문자 발송 |
| 미입금 예약 자동 취소 | 운영자가 매일 21:00에 직접 취소 |
| 고객 회원가입과 로그인 | 고객은 로그인 없이 예약 |
| 고객이 직접 예약 조회, 변경, 취소 | 문자로 운영자에게 요청 |
| 여러 농장, 여러 상품 | 농장 1곳, 상품 1개 |
| AI 농장 추천 | 하지 않음 (9장 참고) |
| 체험 후 설문 화면 | 구글 폼 |
| 농장주용 화면 | 농장주는 웹을 쓰지 않음 |
| 주소, 이메일, 생년월일 입력 | 받지 않음 |

| **P1** | 신청 후 24시간이 지난 입금 대기 예약 강조 | 운영자가 시각을 직접 계산해야 함 |
| **P2** | 농장 사진과 소개 꾸미기 | 글만 있는 소박한 화면 |
| **P2** | 체험 1개월 뒤 개인정보 일괄 삭제 버튼 | Supabase 화면에서 직접 지움 |
| **P2** | 문자 예시 문장을 복사하는 버튼 | 메모장에서 복사 |

**11/2까지 P0을 완성하지 못하면** 사이트 대신 미리 만들어 둔 **구글 폼 + 구글 시트**로 예약을 받는다(결정 12).
구글 폼에서는 정원과 중복 예약을 자동으로 막을 수 없으므로, 운영자가 회차가 찰 때마다 선택지를 직접 지운다.

## 9. AI 사용 여부와 실패 시 대응

### 9-1. 서비스 안의 AI: **사용하지 않는다**

- WhyTree의 "AI 농장 추천"은 이번 스펙에서 제외한다. 농장이 1곳뿐이라 추천할 대상이 없다.
- 이번 가설("돈을 내고 예약하는가")은 AI 없이 입금 기록만으로 검증할 수 있다.
- PREMORTEM 3번(AI 예측과 현장의 차이로 신뢰가 떨어짐)의 위험을 이번 검증에 끌어들이지 않는다.
- 외부 농장 제휴로 농장이 여러 곳이 되면 그때 다시 검토한다.

### 9-2. 개발 도구로서의 AI: **사용한다** (Claude Code)

예약 화면, 운영자 화면, Supabase 연결 코드를 Claude Code로 만든다.

| 실패 상황 | 알아채는 신호 | 대응 |
|---|---|---|
| AI가 만든 코드가 정원 초과나 중복 예약을 막지 못함 | 10장 테스트 1 실패 | 배포하지 않는다. 고칠 때까지 테스트 1을 다시 한다. |
| AI가 만든 운영자 화면에 로그인 없이 들어갈 수 있음 | 10장 테스트 3 실패 | 배포하지 않는다. 고객 개인정보가 노출되기 때문이다. |
| 코드를 이해하지 못해 오류를 고칠 수 없음 | 같은 오류를 하루 넘게 고치지 못함 | 기능을 P0 범위로 줄이고, 팀원에게 도움을 요청한다. |
| 11/2까지 P0이 완성되지 않음 | 11/2(월) 저녁에 테스트 3개 중 하나라도 실패 | **구글 폼 + 구글 시트로 전환**하고, 예정대로 11/3에 모집을 시작한다. |
| 모집 기간 중 사이트가 멈춤 | 고객이 "예약이 안 된다"고 연락함, 또는 운영자 화면이 열리지 않음 | 홍보 글의 링크를 **구글 폼으로 교체**하고, 그동안 들어온 예약은 Supabase 화면에서 직접 확인한다. 두 곳의 예약을 합쳐서 정원을 센다. |

## 10. 개발 메모

구현할 때 반드시 지킬 것들이다. 화면 기술과 호스팅은 구현을 시작할 때 정한다.

- **정원과 중복 확인은 데이터베이스 안에서 한다.** 화면에서만 확인하면 두 사람이 동시에 신청했을 때 둘 다 통과할 수 있다. Supabase의 데이터베이스 함수 하나가 "남은 자리 확인 → 같은 번호 건수 확인 → 저장"을 한 번에 처리하게 한다.
- **권한(RLS) 규칙.** RLS는 "누가 어떤 줄을 보고 쓸 수 있는지" 정하는 Supabase 규칙이다.
  - 로그인하지 않은 고객은 예약을 **넣기만 할 수 있고, 읽을 수는 없다.**
  - 고객 화면에는 회차별 **남은 자리 숫자만** 보여준다.
  - 명단 읽기와 상태 변경은 로그인한 운영자만 할 수 있다.
- **시간대.** Supabase는 세계 표준시(UTC)로 저장한다. 화면에 보여주는 입금 마감 시각과 신청 마감(11/11 23:59)은 **한국 시간(KST)** 기준으로 계산한다.
- **운영자 계정.** 입금 담당과 대신할 사람, 그리고 정상섭까지 **3개**를 정상섭이 Supabase에서 직접 만든다. 회원가입 화면은 만들지 않는다.
- **테스트 데이터.** 10장 테스트에서 넣은 예약은 11/3 공개 전에 모두 지운다.
- **화면 기준.** 휴대폰 화면(폭 약 360px)을 기준으로 만들고, PC에서도 깨지지 않는지 확인한다.
- **호스팅 후보.** Vercel이나 Netlify 같은 무료 호스팅을 쓴다.

### 감수하는 위험

- 운영자가 하루 한 번(21:00)만 확인하기 때문에, 입금하지 않은 예약이 자리를 **최대 약 48시간** 묶을 수 있다. 정원이 금방 차는 상황이 오면 확인 횟수를 하루 2회로 늘린다.

## 11. 직접 수행할 테스트 3개

배포 전(11/2 저녁)에 정상섭이 직접 휴대폰과 PC로 수행한다. 셋 다 통과해야 11/3에 홍보 링크를 공개한다.

### 테스트 1 — 정원과 중복 예약이 막히는가

1. 11/14 10시 회차에 서로 다른 전화번호로 테스트 예약을 5건 넣는다.
2. 예약 화면을 새로고침한다.
3. **기대 결과:** 11/14 10시 회차가 "마감"으로 표시되고, 선택할 수 없다.
4. 운영자 화면에서 한 건을 **취소**로 바꾼다. 그런 다음 브라우저 두 개로 그 회차의 **마지막 1자리**에 동시에 "예약 신청"을 누른다.
5. **기대 결과:** 한 건만 성공하고, 다른 한 건은 "자리가 없습니다" 안내를 받는다.
6. 다른 회차에 같은 전화번호로 2건을 예약한 뒤, 하이픈을 넣거나 빼서 같은 번호로 3번째 예약을 시도한다.
7. **기대 결과:** 3번째 예약은 "이미 예약이 2건 있습니다" 안내와 함께 막힌다.

### 테스트 2 — 예약부터 확정, 집계까지 이어지는가

1. 휴대폰으로 `?from=daangn`이 붙은 링크를 연다.
2. 입력 항목을 채우고 예약을 신청한다. "알게 된 경로"는 "지역 커뮤니티"를 고른다.
3. **기대 결과:** 완료 화면에 계좌번호와 복사 버튼, 30,000원, **한국 시간으로 신청 후 24시간 뒤**의 입금 마감 시각, 환불 규칙이 보인다. 복사 버튼을 누르면 계좌번호가 복사된다.
4. 완료 화면을 닫고 예약 화면 맨 아래 "입금 안내" 칸에서 같은 계좌 정보를 확인한다.
5. 운영자 화면에서 이 예약이 **입금 대기**이고, 입금자명과 유입 경로(`daangn`)가 맞게 저장됐는지 확인한다.
6. 상태를 **예약 확정**으로 바꾼다.
7. **기대 결과:** 집계에서 "지인 아닌 입금 팀"과 `daangn` 입금 팀 수가 각각 1 늘어난다.
8. `?from=friend` 링크로 한 번 더 예약하고 확정한다. **기대 결과:** "지인 아닌 입금 팀" 수는 늘어나지 않는다.

### 테스트 3 — 로그인하지 않은 사람은 고객 정보를 볼 수 없는가

1. 로그인하지 않은 브라우저(시크릿 창)에서 운영자 화면 주소를 직접 입력한다.
2. **기대 결과:** 명단이 보이지 않고 로그인 화면으로 이동한다.
3. 예약 화면에서 다른 사람의 이름이나 전화번호를 볼 방법이 있는지 확인한다.
4. **기대 결과:** 예약 화면에는 회차별 남은 자리 숫자만 보이고, 다른 고객의 정보는 어디에도 보이지 않는다.
