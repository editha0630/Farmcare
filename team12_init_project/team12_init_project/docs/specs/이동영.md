# 수확체험 예약 — 사전 신청 페이지 스펙

FarmCare 파일럿 농가의 감(단감) 수확체험에 도시 가족이 사전 신청하는 기능.

## 누구를 위한 기능인가

| 역할 | 누구 | 이 기능에서 하는 일 |
|---|---|---|
| **신청자** | 체험을 원하는 도시 가족 | 사전 신청 페이지에서 신청서를 제출한다 |
| **호스트 농가** | 시골에서 농사짓는 고령 부모님 | 체험 당일 현장에서 가족을 맞이한다. 앱을 쓰지 않고 문자 알림만 받는다 |
| **도시 자녀** | 호스트 농가의 자녀, 도시 거주 | 일손을 도우러 내려가지 않아도 되는 것이 목표다. P0에서는 직접 쓰지 않는다 |
| **FarmCare 팀** | 운영자 | 신청 목록을 확인하고, 일정을 확정하고, 부모님께 문자를 보낸다 |

## 문제가 나타나는 순간

- 가을 감 수확철이 다가오는데 고령 부모님 혼자서는 감을 다 딸 수 없다.
- 도시에 사는 자녀는 주말마다 내려가기 어렵다. 결국 수확하지 못한 감이 나무에 남고 농지는 점점 방치된다.
- 한편 도시 가족은 아이와 함께할 "진짜 농가의 수확"을 찾고 있지만, 이런 농가를 만날 경로가 없다.

## 차별점

개인 농가 수확체험은 이미 있다. FarmCare는 **"일손이 부족한 농가의 실제 수확을 돕는다"**는 점을 내세운다. 가족은 단순한 체험객이 아니라 실제 수확 인력이다.

## 이 기능이 돕는 WhyTree 노드

```
- 농지 걱정없이 지내기
  - 방문(관리) 부담 덜기
    - 농지 방치 막기
      - 수확인력 확보
        - 수확체험 운영
          - [씨앗] 수요 조사        ← 사전 신청 수와 결제 전환율로 검증
          - [씨앗] 예약페이지 제작   ← 이 기능
          - [씨앗] 수확프로그램 설계
```

- 사전 신청 페이지 하나로 **예약페이지 제작**과 **수요 조사**라는 두 씨앗을 함께 검증한다.
- 점선 대안인 "전문인력/기계 공급업자 매칭"은 농협, 지자체, 민간 앱이 이미 하고 있어서 택하지 않았다.

## 사용자가 할 수 있는 것 (P0)

### 신청자 (도시 가족)

1. 사전 신청 페이지에 들어온다. 파일럿 농가, 작물(단감), 수확 기간을 확인한다.
2. **희망 주말**을 고른다. 날짜가 아니라 수확 기간 안의 주말 단위로 고른다.
3. **가족 인원**을 입력한다.
4. **아이 나이**를 입력한다.
5. **연락처**를 입력한다.
6. **안전 수칙**을 읽고 동의에 체크한다. 체크하지 않으면 제출할 수 없다.
7. 제출하면 "신청 완료, 확정 일정은 D-7에 연락드립니다" 안내를 본다. 사전 신청은 무료다.

### FarmCare 팀

1. 제출된 **신청 목록**을 확인한다.
2. 작물 상태와 날씨를 보고 날짜를 정해 D-7에 가족에게 확정 문자를 보낸다. 이 문자에 계좌번호를 안내한다.
3. 입금을 직접 확인하고, 신청 목록에 "결제 완료"로 표시한다.
4. 부모님께 문자를 **직접(수동으로)** 보낸다.
   - D-7: 확정 날짜, 시간, 팀 수, 인원
   - D-1: 리마인드
   - 당일 변경이나 취소가 생기면 즉시

### 호스트 농가 (부모님)

1. 문자로 일정을 받는다.
2. 당일 현장에서 가족을 맞이한다.

## 안전 수칙 (신청 시 동의 대상)

- 사다리 사용 금지. 손이 닿는 가지와 장대 수확만 허용한다.
- 높은 가지는 체험 대상에서 제외한다.
- 어린이는 반드시 보호자와 함께한다.
- 감따기 장대는 성인만 사용한다.

## 운영 정책 (화면에 안내)

- **요금**: 기본 체험비에 단감 1박스를 포함한다. 추가 구매는 박스 단위로 한다.
- **일정**: 수확 기간 단위로 신청받고, D-7에 날짜를 확정한다.
- **우천**: 연기를 우선하고, 연기가 불가능하면 전액 환불한다.
- **호스팅 부담 상한**: 슬롯당 인원 상한을 두고, 하루에 1회만 운영한다.

## 우선순위

| 항목 | 우선순위 |
|---|---|
| 사전 신청 페이지 (희망 주말, 가족 인원, 아이 나이, 연락처, 안전 수칙 동의 → 제출) | **P0** |
| 팀의 신청 목록 확인 | **P0** |
| 안전 수칙 동의 체크 (필수) | **P0** |
| 슬롯당 인원 상한, 하루 1회 운영 | **P0** |
| 부모님께 문자 알림 (팀이 수동 발송) | **P0** |
| D-7 확정 문자에 계좌번호 안내, 팀이 입금 확인 후 신청 목록에 "결제 완료" 표시 | **P0** |
| 결제 기능 (D-7 확정 시 결제 링크) | P1 |
| 문자 자동 발송 | P1 |
| 도시 자녀의 원격 관리 (슬롯 열기, 예약 확인) | P1 |
| 사전 안내 자료 (수확 방법 영상이나 카드) | P1 |
| 농가별 목표 수확량 설정과 체험 후 수확량 기록 | P1 |
| 수확 진행률 표시 ("남은 감 ○○박스") | P1 |
| 여러 농가가 등록하는 마켓플레이스로 확장 | P2 |
| 단감 외 작물과 품종 지원 (예: 대봉의 홍시 안내) | P2 |

## 범위 밖

- 체험자 보험 일괄 가입 (운영 정책으로 따로 다룬다)
- 전문인력/기계 공급업자 매칭, 농지 양도/매각
- 수확프로그램 설계 (별도 씨앗)
- 파일럿 농가 1~3곳을 넘는 확장
- 부모님이 앱을 직접 사용하는 기능

## 수요 검증 기준 (Go/No-Go)

- 오픈 후 **2주 안에 농가당 사전 신청 10팀 이상**
- D-7 확정 이후 **결제 전환율 50% 이상**

> **P0 기간의 결제 전환율 측정**: D-7 확정 문자에 계좌번호를 안내한다. 팀이 입금을 직접 확인하고, 신청 목록에 "결제 완료"로 표시한다. 결제 기능 자체는 P1 그대로 둔다.

## AI 모델과 실패 시 동작

- **AI 모델을 사용하지 않는다.** 일정 확정, 신청 검토, 문자 발송은 모두 FarmCare 팀이 직접 한다.
- 실패할 때는 이렇게 동작한다.
  - **필수 항목 누락이나 안전 수칙 미동의**: 제출을 막고, 빠진 항목을 표시한다.
  - **연락처 형식 오류**: 제출을 막고, 올바른 형식을 안내한다.
  - **제출 저장 실패 (네트워크나 서버 오류)**: 입력값을 그대로 유지하고, "제출되지 않았습니다. 다시 시도해 주세요"를 표시한다. 성공 화면을 보여주지 않는다.
  - **같은 연락처로 같은 주말에 중복 신청**: 접수는 받고, 팀이 목록에서 확인해 정리한다.

## 손으로 하는 점검

1. **정상 제출**: 모든 항목을 채우고 안전 수칙에 동의해 제출한다. 완료 안내가 뜨고, 팀의 신청 목록에 입력한 희망 주말, 가족 인원, 아이 나이, 연락처가 그대로 보이는지 확인한다.
2. **안전 수칙 미동의 차단**: 다른 항목은 모두 채우고 동의 체크만 비운 채 제출한다. 제출이 막히고, 신청 목록에 아무것도 추가되지 않는지 확인한다.
3. **저장 실패 시 입력 보존**: 주소 뒤에 `?simulate=save-fail`을 붙여 신청 페이지를 연다(예: `index.html?simulate=save-fail`). 모든 항목을 채워 제출한다. "제출되지 않았습니다. 다시 시도해 주세요." 메시지가 뜨고, 입력값이 남아 있으며, 성공 화면이 나오지 않는지 확인한다. 팀용 신청 목록에도 추가되지 않아야 한다. (P0 프로토타입은 서버 없이 브라우저 저장소를 쓰므로, 네트워크를 끊어도 저장 실패가 재현되지 않는다.)
