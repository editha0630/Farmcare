## 들어 있는 것 (P0)

| P0 기능 | 어디서 |
|---|---|
| 예약 화면: 체험 정보, 회차 선택, 입력 항목, 개인정보 동의, 휴대폰 화면 기준 | `index.html`, `js/booking.js` |

## 1단계. 데모 모드로 내 컴퓨터에서 실행하기

**데모 모드**는 인터넷 서버 없이, 예약을 **내 브라우저 안에만** 저장하는 연습용 모드입니다.
`js/config.js`의 `SUPABASE_URL`이 비어 있으면 자동으로 데모 모드가 됩니다. 화면 맨 위에 검은 띠로 "데모 모드"라고 표시됩니다.

1. Windows 검색창에 **터미널**(또는 PowerShell)을 입력해서 엽니다.
2. 이 폴더로 이동합니다.

   ```bash
   cd "C:\Users\82104\Downloads\team12_init_project\team12_init_project\team12_init_project\prototypes\정상섭"
   ```

3. 작은 웹 서버를 켭니다. 이 명령은 이 폴더의 파일을 브라우저에 보여주는 역할을 합니다.

   ```bash
   python -m http.server 8000
   ```

   `Serving HTTP on ... port 8000` 이 보이면 켜진 것입니다. **이 창은 닫지 마세요.**
4. 브라우저(크롬)에서 아래 주소를 엽니다.
   - 예약 화면: http://localhost:8000/index.html
   - 운영자 화면: http://localhost:8000/admin.html
   - 데모 운영자 계정: `demo@farmcare.test` / `demo1234`
5. 휴대폰 화면으로 보려면 크롬에서 **F12 → 왼쪽 위 휴대폰 모양 아이콘**(또는 `Ctrl+Shift+M`)을 누릅니다.
6. 끝낼 때는 3번의 터미널 창에서 `Ctrl+C`를 누릅니다.

데모 예약을 모두 지우고 싶으면 크롬에서 **F12 → Application → Local Storage → http://localhost:8000** 을 열고 `farmcare-demo-bookings-v1` 을 지웁니다.

> 데모 모드는 화면과 규칙을 연습하는 용도입니다. **"두 사람이 동시에 마지막 자리를 누르는 상황"**과 **"로그인 안 한 사람이 정보를 볼 수 있는지"**는 Supabase 모드에서만 제대로 확인할 수 있습니다.

## 2단계. Supabase 연결하기 (실제 운영용)

**Supabase**는 무료로 쓸 수 있는 인터넷 데이터베이스입니다. 예약 정보가 여기에 저장되므로 팀원 누구나 같은 명단을 봅니다.

### 2-1. 프로젝트 만들기
1. https://supabase.com 에 가입하고 **New project**를 누릅니다.
2. 이름은 `farmcare-persimmon`, 지역(Region)은 **Northeast Asia (Seoul)** 을 고릅니다.
3. 데이터베이스 비밀번호는 아무 곳에도 공유하지 말고 따로 적어둡니다.

### 2-2. 데이터베이스 설정 붙여넣기
1. 왼쪽 메뉴 **SQL Editor → New query** 를 엽니다.
2. `supabase/schema.sql` 파일을 메모장으로 열어 **전체를 복사**해서 붙여넣고 **Run** 을 누릅니다.
3. `Success. No rows returned` 가 나오면 성공입니다.
4. 왼쪽 **Table Editor** 에 `slots`(회차 4줄), `bookings`(비어 있음), `operators` 가 보이는지 확인합니다.

### 2-3. 아무나 가입하지 못하게 막기 (중요)
1. 왼쪽 **Authentication → Sign In / Providers**(또는 Settings)로 갑니다.
2. **Allow new users to sign up** 을 **끕니다.** 저장합니다.

### 2-4. 운영자 계정 3개 만들기
1. **Authentication → Users → Add user → Create new user** 를 누릅니다.
2. 운영자 이메일과 비밀번호를 넣고, **Auto Confirm User** 를 체크한 뒤 만듭니다. (정상섭, 입금 담당, 대신할 사람 3명)
3. 다시 **SQL Editor** 에서 아래를 실행합니다. 이메일은 방금 만든 것으로 바꿉니다.

   ```sql
   insert into public.operators (email) values
     ('정상섭@이메일'),
     ('입금담당@이메일'),
     ('대신할사람@이메일')
   on conflict do nothing;
   ```

   `operators` 에 등록된 이메일만 명단을 볼 수 있습니다. 계정이 있어도 여기에 없으면 "운영자로 등록되지 않은 계정"이라고 나옵니다.

### 2-5. 웹사이트와 연결하기
1. **Project Settings → API**(또는 **Data API / API Keys**)로 갑니다.
2. **Project URL** 과 **anon public** 키를 복사합니다.
3. `js/config.js` 를 메모장으로 열어 붙여넣고 저장합니다.

   ```js
   SUPABASE_URL: 'https://xxxx.supabase.co',
   SUPABASE_ANON_KEY: 'eyJhbGciOi...',
   ```

   > anon 키는 웹사이트에 공개되어도 괜찮은 키입니다. 권한 규칙(RLS) 때문에 이 키로는 예약을 **넣기만** 할 수 있고, 명단을 읽을 수 없습니다.
   > 반대로 **service_role** 키는 절대 넣으면 안 됩니다. 모든 권한을 가진 키입니다.

4. 1단계처럼 서버를 켜고 예약 화면을 새로고침합니다. 맨 위 검은 "데모 모드" 띠가 **사라졌으면** Supabase와 연결된 것입니다.

## 3단계. 직접 수행할 테스트 3개 (스펙 11장)

**Supabase 모드에서** 해야 합니다. 셋 다 통과해야 11/3에 홍보 링크를 공개합니다. 결과는 아래 표의 칸에 적어두세요.

### 테스트 1 — 정원과 중복 예약이 막히는가

1. 예약 화면에서 **11/14 오전 10시** 회차에 서로 다른 전화번호(예: `010-0000-0001` ~ `010-0000-0005`)로 5건을 예약합니다. 완료 화면의 **다른 예약 하기**를 누르면 다음 예약을 할 수 있습니다.
2. 예약 화면을 새로고침합니다.
   - ✅ 기대 결과: 11/14 오전 10시가 **"마감"** 으로 보이고 고를 수 없습니다.
3. 운영자 화면에서 그중 1건을 **취소**합니다.
4. **크롬 창 두 개**(하나는 일반 창, 하나는 `Ctrl+Shift+N` 시크릿 창)에 예약 화면을 열고, 둘 다 11/14 오전 10시를 고르고 서로 다른 번호를 입력합니다. 두 창의 **예약 신청** 버튼을 최대한 동시에 누릅니다.
   - ✅ 기대 결과: 한 창만 완료 화면이 나오고, 다른 창은 **"방금 이 회차의 자리가 모두 찼습니다"** 가 나옵니다.
5. 다른 회차에 같은 번호로 2건을 예약합니다. 한 번은 `010-7777-8888`, 한 번은 `01077778888` 처럼 하이픈을 다르게 씁니다. 그리고 같은 번호로 3번째 예약을 시도합니다.
   - ✅ 기대 결과: 3번째는 **"이 전화번호로 이미 예약이 2건 있습니다"** 가 나오며 막힙니다.

> 동시에 누르는 것이 어렵다면 Supabase **SQL Editor**에서 아래를 실행해 마지막 자리가 1개 남은 회차에 2건을 연달아 넣어보세요. 두 번째는 `"code" : "full"` 이 나와야 합니다.
> ```sql
> select public.create_booking('1114-10','테스트A','01090000001',2,0,0,'테스트A','기타',true);
> select public.create_booking('1114-10','테스트B','01090000002',2,0,0,'테스트B','기타',true);
> ```

### 테스트 2 — 예약부터 확정까지 이어지는가

1. **휴대폰**으로 예약 화면을 엽니다. (휴대폰으로 열려면 4단계처럼 인터넷에 올려야 합니다. 그 전에는 크롬의 휴대폰 화면 보기로 대신합니다.)
2. 입력 항목을 채우고 예약을 신청합니다.
   - ✅ 기대 결과: 완료 화면에 계좌번호와 복사 버튼, **30,000원**, **지금부터 24시간 뒤의 한국 시간**이 입금 마감으로 보입니다.
3. **계좌번호 복사**를 누르고 메모장 등에 붙여넣어 봅니다.
   - ✅ 기대 결과: 숫자만 붙여넣어집니다.
4. 완료 화면을 닫고 예약 화면 맨 아래 **입금 안내** 칸을 봅니다.
   - ✅ 기대 결과: 같은 계좌 정보와 복사 버튼이 보입니다.
5. 운영자 화면에서 이 예약을 찾습니다.
   - ✅ 기대 결과: 상태가 **입금 대기**이고, 이름, 번호, 인원, 입금자명, 알게 된 경로가 입력한 대로 보입니다.
6. **입금 확인 → 확정** 을 누릅니다.
   - ✅ 기대 결과: 상태가 **예약 확정**으로 바뀝니다.

> 스펙의 테스트 2 중 "유입 꼬리표(`?from=`)와 집계" 확인 단계는 **P1 기능**이라 이번 P0 프로토타입에는 아직 해당하지 않습니다.

### 테스트 3 — 로그인하지 않은 사람은 고객 정보를 볼 수 없는가

1. **시크릿 창**(`Ctrl+Shift+N`)에서 운영자 화면 주소를 엽니다.
   - ✅ 기대 결과: 명단이 아니라 **로그인 화면**이 나옵니다.
2. 시크릿 창에서 예약 화면을 열고 **F12 → Console** 에 아래를 붙여넣고 Enter를 누릅니다. 로그인하지 않은 사람이 명단을 직접 달라고 요청해 보는 것입니다.

   ```js
   (await window.supabase.createClient(APP_CONFIG.SUPABASE_URL, APP_CONFIG.SUPABASE_ANON_KEY).from('bookings').select('*'))
   ```

   - ✅ 기대 결과: `data` 가 비어 있거나 `error` 에 `permission denied` 가 나옵니다. **이름이나 전화번호가 하나라도 보이면 실패**입니다.
3. 예약 화면 어디에도 다른 고객의 이름이나 전화번호가 보이지 않는지 확인합니다.
   - ✅ 기대 결과: 회차별 **남은 자리 숫자만** 보입니다.

## 자주 생기는 문제

| 증상 | 원인과 해결 |
|---|---|
| `python` 을 찾을 수 없다고 나옴 | `py -m http.server 8000` 으로 바꿔 실행합니다. |
| 화면은 나오는데 "남은 자리를 불러오지 못했습니다" | `config.js` 의 URL이나 키가 틀렸거나, `schema.sql` 을 실행하지 않았습니다. F12 → Console 의 빨간 글씨를 확인합니다. |
| 운영자 로그인 후 "운영자로 등록되지 않은 계정" | 2-4의 `insert into public.operators` 를 실행하지 않았거나 이메일 철자가 다릅니다. |
| 맨 위에 계속 "데모 모드"가 보임 | `config.js` 를 저장했는지, 브라우저를 새로고침했는지 확인합니다. |
| 신청 마감 시각을 바꾸고 싶음 | `js/config.js` 의 `BOOKING_CLOSES_AT` 과 `supabase/schema.sql` 의 `closes_at` 을 **둘 다** 바꾸고, schema.sql을 다시 실행합니다. |
